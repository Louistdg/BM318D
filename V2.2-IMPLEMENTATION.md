La version 2.2.0 est installée dans <repertoire d’installation> et répond sur http://127.0.0.1:31880/. Le gestionnaire « Connecteurs IA / MCP » se trouve en bas à droite. Recharger la page pour charger le nouveau gestionnaire. Aucun fournisseur ni serveur MCP n’a été activé automatiquement.

## Périmètre livré

- Registre SQLite additif : nom, type, version du contrat (1), configuration publique, capacités calculées, activation, état, quotas cumulés.
- Adaptateurs Ollama, OpenAI-compatible Chat Completions, Anthropic Messages et Gemini generateContent ; appels HTTP avec délai, sortie bornée et refus des redirections. HTTPS obligatoire hors boucle locale. Les proxys d’environnement sont désactivés pour ces appels.
- Gestionnaire graphique : ajouter, modifier, tester, activer, désactiver, supprimer ; clés masquées, gestion séparée du coffre ; attribution/retrait par agent, modèle spécifique, priorité de secours et liste d’outils.
- Jobs : les agents attribués utilisent leurs fournisseurs dans l’ordre de priorité. Échec réseau, réponse JSON invalide ou quota épuisé provoquent une tentative du fournisseur suivant. Si toutes les attributions échouent, le job échoue ; aucune fuite vers l’ancien Ollama. Les agents sans attribution conservent leur fonctionnement historique. Les propositions restent soumises à validation et approbation avant écriture.
- Quotas persistants : réservation atomique avant appel, concurrence testée ; les erreurs et interruptions consomment le quota. Compteurs cumulés conservés lorsqu’on modifie ou désactive un connecteur. Un plafond de sortie par appel et un budget cumulé de tokens de sortie réservés sont disponibles.
- Secrets : Windows Credential Manager, persistance locale pour l’utilisateur Windows, référence UUID propre à chaque connecteur. Ni clé dans la configuration ni clé renvoyée dans les API de lecture. Aucune solution de secours en clair. Suppression du connecteur supprime aussi sa clé. Les erreurs de fournisseurs sont expurgées et une clé renvoyée littéralement dans une réponse IA est masquée.
- Journal séparé : horodatage, connecteur, agent des générations, opération, statut, durée, réserve de sortie. Aucun contenu de prompt, réponse ou en-tête d’authentification dans ce journal. Les 100 dernières entrées sont consultables dans le gestionnaire.
- Client MCP officiel Python mcp 2.1.1 déjà installé : connexion Streamable HTTP locale ou distante, initialisation et découverte des outils/schémas, sans exposition de racines ni délégation de génération au serveur.

Vérifiés par lecture et tests HTTP : écoute boucle locale, validation Host/Origin, jeton de session, cookie HttpOnly/SameSite Strict, limite de corps, validation JSON, limitation de débit et isolation par projet.

Conséquence : aucune exécution de nouvel outil MCP ou plugin, même annoncé en lecture seule, même avec approved=true. La route d’appel refuse et journalise la tentative. Aucun réglage ne lève ce verrou. Aucun serveur stdio n’est lancé et aucun paquet de plugin n’est exécuté. Une confirmation humaine est requise pour chaque test réseau ; l’autorisation réseau permanente d’un fournisseur doit être cochée avant son usage par les agents attribués.

Les actions sensibles historiques restent dans leurs flux existants ; elles n’ont pas été étendues aux plugins. Le code Git historique et le bac à sable existant ne sont pas certifiés par cette mission.

## Limites et suites nécessaires

1. Exécution d’outils MCP, plugins sensibles et transport stdio volontairement non livrés actifs : il faut d’abord démontrer un confinement réseau/secrets et ajouter un mécanisme de consentement lié à chaque outil, arguments et agent. Les annotations d’un serveur ne suffisent pas.
2. Pas d’appel à une API commerciale : aucune clé utilisateur fournie ou consommée. Les formats ont été testés avec des serveurs HTTP locaux ; cela ne prouve pas une compatibilité avec tous les modèles commerciaux. L’endpoint Ollama réel était injoignable ; aucun résultat d’inférence locale réelle n’est revendiqué.
3. Le budget porte sur la sortie maximale réservée, pas sur le coût monétaire ni les tokens d’entrée facturés. Pas de remise à zéro périodique, de tarification par fournisseur ni de réconciliation de factures. Les réserves ne sont pas remboursées après un échec.
4. La planification historique reste sur son chemin Ollama ; les attributions du registre sont utilisées pour les jobs d’agents. Pas de boucle autonome d’appels d’outils.
5. La découverte MCP couvre la première page d’outils. OAuth, anciens transports SSE, pagination et exécution ne sont pas implémentés. L’authentification disponible est Bearer via le coffre.
6. Une sauvegarde SQLite ne transporte pas les secrets Windows. Après restauration sur un autre compte ou poste, ressaisir les clés. Une restauration ancienne peut référencer une clé supprimée depuis ; le connecteur doit alors être reconfiguré.
7. Délai fournisseur = délai réseau, pas garantie absolue contre un serveur qui transmet très lentement. Aucune validation de confinement réseau complet ni audit de tous les modules historiques n’est revendiqué.

Pour utiliser un fournisseur : ajouter un connecteur avec l’URL de base adéquate (Ollama : http://127.0.0.1:11434 ; OpenAI : https://api.openai.com/v1 ; Anthropic : https://api.anthropic.com/v1 ; Gemini : https://generativelanguage.googleapis.com/v1beta), saisir le modèle et les quotas, autoriser le réseau, enregistrer la clé dans le coffre si nécessaire, activer, tester puis attribuer aux agents. Les priorités croissantes règlent le basculement. Ne jamais mettre de clé dans un nom, une URL ou un modèle.

Documentation consultée : [SDK MCP officiel](https://py.sdk.modelcontextprotocol.io/client/transports/), [API Gemini](https://ai.google.dev/api/generate-content), [exemples Anthropic officiels](https://github.com/anthropics/skills/blob/main/skills/claude-api/curl/examples.md). Le code et les signatures du SDK installé ont aussi été inspectés.
